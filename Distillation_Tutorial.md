# Model Distillation Notes

## Context

Founding paper: Hinton, Vinyals, Dean, "Distilling the Knowledge in a Neural Network", 2015      
- https://arxiv.org/pdf/1503.02531

Problem: the most capable models are huge, so they are expensive to run in production (latency, GPU cost, energy).

Solution: use a large model not in production, but as a data generator to train a smaller, specialized model.

## Method 1: Hinton-style distillation (soft labels)

Hinton's original approach does not target the generated text itself, but the full probability distribution the model produces at each generation step (the "soft target"), not just the single most likely token.

Concretely: at each position, an LLM computes a probability for every possible token in the vocabulary (via softmax). The final chosen token is only the peak of that distribution. Hinton showed that the rest of the distribution carries useful information ("dark knowledge"): for example, if the model hesitates between "cat" and "dog" at 40% each, that says something about the semantic proximity of these concepts that the single final word ("cat") does not. A student model trained to reproduce this full distribution (not just the final word) learns faster and better.

**Why this is hard in practice with closed models (GPT, Claude, Gemini):**
Commercial APIs do not return the full probability distribution over the entire vocabulary at each token. At best they return logprobs for the top N most likely tokens (N=20 for OpenAI, for example), never the full distribution over a 100k+ token vocabulary. Hinton-style distillation is therefore impossible with a proprietary model.

**Workaround:** use an open-weight model (Llama, Qwen, Mistral...) where raw logits are directly accessible locally, giving access to the full distribution. This is what some labs do to distill their own model families internally.

## Method 2: SFT-based distillation (Supervised Fine-Tuning)

This is the method actually accessible without weight access.

Principle: generate a corpus of (prompt, response) pairs by querying the large model on a given subject, then train a small model with standard supervised fine-tuning on that corpus. The probability distribution is not captured, just the final text produced by the large model, used as ground truth.

- Specialized version: the corpus covers only one domain or task. The student model becomes very good within that narrow scope, without matching the teacher's general versatility.
- General-purpose version (what DeepSeek, Qwen, etc. do): same principle but at much larger scale and across all domains, to produce a smaller model that approaches the teacher's general capabilities.

## Example script (finetuning.py)

```python
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig
from trl import SFTTrainer, SFTConfig
import torch

BASE_MODEL = "Qwen/Qwen2.5-3B-Instruct"  # example small student model
DATASET_PATH = "prompts.json"

dataset = load_dataset("json", data_files=DATASET_PATH, split="train")

# 4-bit quantization to reduce required GPU memory (QLoRA)
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)

tokenizer = AutoTokenizer.from_pretrained(BASE_MODEL)
model = AutoModelForCausalLM.from_pretrained(
    BASE_MODEL,
    quantization_config=bnb_config,
    device_map="auto",
)

# LoRA configuration
peft_config = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules="all-linear",  # see LoRA vs Full Fine-Tuning section below
)

training_args = SFTConfig(
    output_dir="./output-distilled-model",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    logging_steps=10,
    save_strategy="epoch",
    bf16=True,
)

trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    peft_config=peft_config,
)

trainer.train()
trainer.save_model("./output-distilled-model")
```

## Expected SFT format for HuggingFace

The instruction/output pair format (Alpaca-style) or the chat-message format below are both standard, consumed directly by `datasets.load_dataset("json", ...)` and compatible with `SFTTrainer` from the `trl` library, which automatically applies the tokenizer's chat template when the dataset is in `messages` format.

```json
{"instruction": "Explain how X works", "input": "", "output": "response generated by the large model"}
```

```json
{"messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}
```

## LoRA vs Full Fine-Tuning

There are two main ways to adapt a pretrained model's weights to a new task: Full Fine-Tuning (FFT), which updates every weight in the model, and LoRA (Low-Rank Adaptation), which freezes the base model and only trains small low-rank matrices inserted into its layers. FFT gives the model the most freedom to change but is expensive and can overwrite general capabilities in the process. LoRA is far cheaper and safer, at the cost of slightly less flexibility to change the model's behavior.

| | LoRA | Full Fine-Tuning |
| --- | --- | --- |
| Trained parameters | Small low-rank matrices added to layers (rest is frozen) | All model weights |
| Memory/GPU cost | Low, fits on a single consumer GPU with quantization | High, requires multiple high-end GPUs |
| Catastrophic forgetting risk | Low (base model stays intact) | High (model can lose general capabilities while specializing) |
| Quality on target task | Good, sometimes slightly below FFT | Maximal |
| Portability | The adapter is small (a few MB to a few hundred MB), easy to share | The full model must be redistributed |

**"LoRA all linear" (`target_modules="all-linear"` in peft):** instead of applying LoRA only to the attention matrices (query/value, the lightest historical configuration), adapters are applied to every linear layer in the model, including the feedforward layers (gate_proj, up_proj, down_proj) and output projections (o_proj). This increases the number of trainable parameters compared to a minimal LoRA setup, but stays far below a full fine-tune. The idea is sound: by covering more layers, the adapter approaches the expressiveness of a full fine-tune, while keeping LoRA's main advantage, namely that the base model stays frozen and is therefore protected from catastrophic forgetting.
